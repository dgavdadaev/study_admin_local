# Введение

## Цель работы  

Изучение возможностей протокола STP и его модификаций по обеспечению отказоустойчивости сети, агрегированию интерфейсов и перераспределению нагрузки между ними.

# Процесс работы

## Формирование резервного соединения между коммутаторами

В логической рабочей области Cisco Packet Tracer была изменена топология сети с целью организации резервного соединения между коммутаторами.

Изначально соединение между коммутаторами msk-donskaya-sw-1 и msk-donskaya-sw-4 было заменено на соединение между msk-donskaya-sw-1 (Gig0/2) и msk-donskaya-sw-3 (Gig0/2).

На коммутаторе msk-donskaya-sw-3 интерфейс Gig0/2 был переведен в транковый режим:

interface gig0/2  
switchport mode trunk  

Дополнительно соединение между коммутаторами msk-donskaya-sw-1 и msk-donskaya-sw-4 было организовано через интерфейсы Fa0/23, которые также были настроены в транковом режиме.

В результате было сформировано резервное соединение, обеспечивающее отказоустойчивость сети.

## Настройка режима PortFast

Для ускорения перехода портов в рабочее состояние на интерфейсах, к которым подключены серверы, был настроен режим PortFast.

На коммутаторе msk-donskaya-sw-2:

interface fa0/1  
spanning-tree portfast  

interface fa0/2  
spanning-tree portfast  

На коммутаторе msk-donskaya-sw-3:

interface fa0/1  
spanning-tree portfast  

interface fa0/2  
spanning-tree portfast  

В результате настройки порты, подключенные к конечным устройствам, начали переходить в состояние Forwarding без задержек, что повысило скорость инициализации соединений.

## Настройка агрегированного соединения (EtherChannel)

Между коммутаторами msk-donskaya-sw-1 и msk-donskaya-sw-4 было сформировано агрегированное соединение, объединяющее интерфейсы Fa0/20 – Fa0/23.

На коммутаторе msk-donskaya-sw-1 была выполнена следующая конфигурация:

interface range fa0/20 - 23  
channel-group 1 mode on  
exit  
interface port-channel 1  
switchport mode trunk  

В процессе настройки были выявлены ошибки несовместимости параметров интерфейсов (различия duplex), что привело к временной приостановке некоторых портов.

![Ошибка при настройке EtherChannel](Screenshot_13.png){ #fig:013 width=80% }

После устранения несоответствий конфигурации агрегирование было успешно выполнено.

На коммутаторе msk-donskaya-sw-4 была выполнена аналогичная настройка:

interface range fa0/20 - 23  
no switchport access vlan 104  
exit  
interface range fa0/20 - 23  
channel-group 1 mode on  
exit  
interface port-channel 1  
switchport mode trunk  

В результате был создан логический интерфейс port-channel 1, объединяющий несколько физических каналов.

## Контрольные вопросы

**1. Какую информацию можно получить при помощи команды show spanning-tree vlan?**  
Данная команда позволяет получить информацию о состоянии протокола STP для конкретного VLAN:

- идентификатор корневого коммутатора (Root ID);
- приоритет и MAC-адрес корневого устройства;
- стоимость пути до корневого моста;
- роли портов (Root, Designated, Alternate);
- состояние портов (Forwarding, Blocking);
- параметры таймеров (Hello Time, Max Age, Forward Delay).

Пример вывода для корневого коммутатора содержит строку:
- This bridge is the root  

Для не корневого коммутатора указывается порт, ведущий к корню:
- Root port — интерфейс с наименьшей стоимостью пути.

**2. При помощи какой команды можно определить режим работы STP?**  
Для определения режима работы используется команда:

- show spanning-tree summary  

В выводе указывается используемый режим, например:
- Spanning tree mode: pvst  
- Spanning tree mode: rapid-pvst  

**3. Для чего используется режим PortFast?**  
Режим PortFast применяется для портов, подключённых к конечным устройствам (ПК, серверы), и позволяет:

- ускорить переход порта в состояние Forwarding;
- избежать задержек, связанных с состояниями Listening и Learning;
- ускорить получение сетевых параметров (например, DHCP).

Использовать PortFast следует только на портах, не подключённых к другим коммутаторам.

**4. В чем состоит принцип работы агрегированного интерфейса?**  
Агрегированный интерфейс (EtherChannel) объединяет несколько физических каналов в один логический канал (port-channel).

Это позволяет:
- увеличить пропускную способность соединения;
- обеспечить балансировку нагрузки;
- повысить отказоустойчивость (при отказе одного канала остальные продолжают работать).

**5. В чем различия между LACP, PAgP и статическим агрегированием?**  

- LACP (IEEE 802.3ad) — открытый стандарт, автоматически согласует параметры каналов между устройствами;  
- PAgP — проприетарный протокол Cisco, выполняет аналогичную функцию согласования;  
- статическое агрегирование (mode on) — не использует протоколы согласования, требует ручной настройки на обоих устройствах.

Основное отличие заключается в наличии автоматического согласования и совместимости между устройствами разных производителей.

**6. При помощи каких команд можно проверить состояние EtherChannel?**  

Для проверки состояния агрегированного канала используются команды:

- show etherchannel summary — отображает общее состояние EtherChannel;  
- show etherchannel port-channel — показывает информацию о логическом интерфейсе;  
- show interfaces port-channel 1 — отображает параметры конкретного агрегированного интерфейса;  
- show running-config interface port-channel 1 — показывает конфигурацию port-channel.
