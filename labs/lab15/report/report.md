## Контрольные вопросы

### 1. Какие протоколы относятся к протоколам динамической маршрутизации?

Протоколы динамической маршрутизации обеспечивают автоматический обмен маршрутной информацией между маршрутизаторами, избавляя администратора от необходимости вручную прописывать каждый маршрут.

К основным протоколам относятся:

**RIP (Routing Information Protocol)** — дистанционно-векторный протокол, использующий количество переходов (hop count) в качестве метрики. Максимальный порог — 15 переходов, поэтому область применения ограничена небольшими сетями.

**OSPF (Open Shortest Path First)** — протокол состояния каналов, формирующий полную карту сети и вычисляющий кратчайший путь с помощью алгоритма SPF. Применяется в сетях среднего и крупного масштаба.

**EIGRP (Enhanced Interior Gateway Routing Protocol)** — усовершенствованный дистанционно-векторный протокол Cisco с составной метрикой, учитывающей пропускную способность, задержку, надёжность и загрузку канала.

**IS-IS (Intermediate System to Intermediate System)** — протокол состояния каналов, схожий по архитектуре с OSPF, широко используемый в сетях операторов связи.

**BGP (Border Gateway Protocol)** — внешний протокол, предназначенный для обмена маршрутами между автономными системами: сетями провайдеров и крупными корпоративными инфраструктурами.

По области применения протоколы делятся на две группы:

**IGP (Interior Gateway Protocol)** — протоколы внутренней маршрутизации в пределах одной автономной системы: RIP, OSPF, EIGRP, IS-IS.

**EGP (Exterior Gateway Protocol)** — протоколы межсистемной маршрутизации, главным представителем которых является BGP.

### 2. Охарактеризуйте принципы работы протоколов динамической маршрутизации.

Динамическая маршрутизация основана на автоматическом построении и поддержании таблиц маршрутизации. После активации протокола маршрутизаторы начинают обмениваться служебными сообщениями, накапливают информацию о топологии сети и самостоятельно определяют оптимальные пути передачи трафика.

Типовой процесс работы включает несколько последовательных этапов.

Сначала маршрутизаторы обнаруживают соседей. В OSPF для этого используются Hello-пакеты: если параметры двух устройств совпадают, между ними устанавливается отношение соседства.

Затем следует обмен маршрутной информацией: устройства сообщают друг другу, какие сети им известны, через какие интерфейсы они доступны и с какой стоимостью.

На основе полученных данных каждый маршрутизатор самостоятельно рассчитывает наилучший маршрут. Критерий выбора определяется метрикой, которая в разных протоколах рассчитывается по-разному: в RIP — по числу переходов, в OSPF — по стоимости, связанной с пропускной способностью интерфейсов, в EIGRP — по совокупности нескольких параметров канала, в BGP — по заданным политикам и атрибутам маршрута.

После расчёта оптимальный маршрут вносится в таблицу маршрутизации. При изменении топологии — отказе канала или недоступности соседа — протокол автоматически пересчитывает маршруты и выбирает новый доступный путь.

В данной работе этот механизм был продемонстрирован на практике: отключение VLAN **6** сделало основной маршрут до Сочи недоступным, OSPF перестроил таблицы и направил трафик через альтернативный канал VLAN **7**. После восстановления VLAN **6** протокол вновь пересчитал маршруты и переключил трафик на основной путь.

### 3. Опишите процесс обращения устройства из одной подсети к устройству из другой подсети по протоколу динамической маршрутизации.

Когда конечное устройство формирует пакет для узла в другой подсети, оно сравнивает IP-адрес получателя со своей сетевой маской. Убедившись, что адрес назначения находится вне локальной подсети, устройство направляет пакет на шлюз по умолчанию — ближайший маршрутизатор.

Перед отправкой кадра необходимо установить MAC-адрес шлюза. Для этого используется протокол **ARP**: отправитель рассылает широковещательный запрос, маршрутизатор отвечает своим MAC-адресом. После этого формируется Ethernet-кадр, в котором IP-адреса источника и назначения соответствуют конечным узлам, тогда как MAC-адрес назначения указывает на шлюз.

Приняв кадр, маршрутизатор извлекает из него IP-пакет, находит в таблице маршрутизации запись для сети назначения и определяет следующий узел. При использовании OSPF этот маршрут был получен в ходе предварительного обмена LSA-пакетами между маршрутизаторами.

На каждом последующем маршрутизаторе повторяется аналогичная процедура: приём кадра, просмотр таблицы маршрутизации, выбор следующего перехода, формирование нового Ethernet-кадра с обновлёнными MAC-адресами. IP-адреса источника и назначения при этом остаются неизменными на протяжении всего пути — меняются только MAC-адреса на каждом участке.

Когда пакет достигает маршрутизатора конечного сегмента, тот определяет, что сеть назначения подключена к нему напрямую, выясняет MAC-адрес получателя с помощью ARP и передаёт кадр конечному устройству. Принявший пакет узел формирует ICMP Echo Reply, который возвращается отправителю по аналогичному маршруту согласно таблицам маршрутизации.

### 4. Опишите выводимую информацию при просмотре таблицы маршрутизации.

Команда `show ip route` отображает полную картину известных маршрутизатору сетей и способов их достижения.

В начале вывода приводится легенда кодов маршрутов:

**C** — directly connected — сеть непосредственно подключена к интерфейсу маршрутизатора.
**L** — local — собственный IP-адрес интерфейса.
**S** — static — маршрут, добавленный вручную.
**S\*** — маршрут по умолчанию; применяется при отсутствии более конкретного совпадения.
**O** — маршрут, полученный от соседних OSPF-маршрутизаторов.
**R** — маршрут, полученный через RIP.
**D** — маршрут, полученный через EIGRP.

Строка **Gateway of last resort** указывает адрес шлюза последней надежды, на который отправляется трафик, если в таблице нет подходящей записи.

Каждая запись маршрута включает следующие поля: сеть назначения с префиксом, код источника маршрута, административную дистанцию и метрику в квадратных скобках, адрес следующего перехода, время существования записи и выходной интерфейс.

Пример OSPF-маршрута:

`O 10.130.0.0/24 [110/2] via 10.128.255.10, 00:01:10, FastEthernet0/1.7`

Здесь **O** означает источник — OSPF; **10.130.0.0/24** — сеть назначения; **110** — административная дистанция OSPF; **2** — метрика маршрута; **10.128.255.10** — адрес следующего маршрутизатора; **00:01:10** — время с момента последнего обновления; **FastEthernet0/1.7** — выходной интерфейс.

Для напрямую подключённых сетей запись выглядит иначе:

`C 10.128.255.8/30 is directly connected, FastEthernet0/1.7`

Это означает, что сеть находится непосредственно на указанном интерфейсе и промежуточный маршрутизатор не требуется.

Запись с кодом **L** указывает конкретный адрес интерфейса самого маршрутизатора:

`L 10.128.255.9/32 is directly connected, FastEthernet0/1.7`

Совокупность этих записей позволяет определить, какие сети доступны маршрутизатору, каким способом получен каждый маршрут, через какой интерфейс и следующий узел будет передан пакет к конкретной сети назначения.
